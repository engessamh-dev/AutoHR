AutoHR attachment editor - Production manual-only behavior (2026-10-08)

Final requested behavior
The user changed scope to remove automatic Smart/offline processing from Production and
retain manual boundary selection and rotation. Automatic-localization work is no longer
a Production deliverable. No further detector accuracy work is required for this request.

Implementation
- Production title and upload choice: manual attachment boundary selection and rotation.
- Four manually draggable/keyboard-adjustable corners, zoom, Fit and reset remain.
- Perspective cropping uses the selected original-resolution corners.
- 90-degree output rotation, result preview, explicit save/cancel and original preservation remain.
- Production hides re-detection, confidence controls, contrast enhancement and diagnostics.
- Production never starts automatic detection from legacy saved auto_detect=true settings.
- Rust build policy forces auto_detect=false and enhancement=0 outside debug builds.
- Direct automatic re-detection commands are rejected outside debug builds.
- Backend provides automatic_detection_available; the UI also requires import.meta.env.DEV.
- Development can retain experimental detection/debug tools. They are unavailable in the
  standard Production release configuration. The manual editor label is used in both modes.
- The existing shared attachment bridge remains; employee, ID and archive attachments use
  the same manual crop/rotation implementation and association/save permissions.

Earlier scanner fixes and private diagnostic fixtures remain in the Development workspace.

Verification approach
Rust tests exercise the build policy with Production=false-development inputs, including
legacy auto_detect=true and enhancement=2. Scanner integration tests use isolated databases
and temporary files to verify association, original preservation, permissions and rollback.
Browser tests compile only the component in memory with import.meta.env.DEV=false and use
mocked IPC. This checks Production UI behavior without creating an application build,
installer, release files or production database access. The manual editor ignores injected
trusted detection corners, starts from full-image manual corners, sends manually edited
corners and rotation=90 to render, and enables save only after result preview.
Production settings tests verify that automatic detection/contrast controls cannot be
re-enabled, while JPEG quality is preserved. The complete test results follow below.
