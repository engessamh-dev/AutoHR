AutoHR — تقرير التحقق والتحديث
التاريخ: 2026-10-08

النتيجة
قواعد الإنتاج والتطوير والنسخة المضمّنة اجتازت SQLite integrity_check.
لا توجد مخالفات foreign_key_check، أو أعمدة مطلوبة ناقصة بعد التحديث،
أو ملفات مفقودة مرتبطة بسجلات الموظفين والوثائق الحالية.
فُحصت بيانات الإنتاج أولًا للقراءة فقط. بعد تفويض المستخدم بتنظيف البيانات
التجريبية، حُذفت السجلات الوصفية القديمة والملفات غير المرتبطة بعد أخذ نسخة كاملة.

التحديثات المنفّذة
- إصلاح تحذيرات Rust واجتياز Clippy مع -D warnings.
- تحديث PDF.js وPostCSS وتبعياتهما الأمنية، وترحيل Tailwind إلى 4.3.3
  وإضافة PostCSS الخاص به مع الحفاظ على التنسيق وإزالة autoprefixer غير اللازم.
- تحديث Tauri إلى 2.12.1 ومكتبات الحوار والإشعارات، وتحديث quick-xml
  وanyhow وevent-listener لإزالة التنبيهات القابلة للإصلاح.
- تحديث مخطط document_metadata وسكربت تجهيز القاعدة.
- إضافة أعمدة الميلاد ومعلومات نسخ الصور الناقصة للقاعدة المضمّنة، بعد
  تجربة الترحيل على نسخة معزولة. جميع السجلات السابقة محفوظة.
- إضافة التحقق من مرفقات الزوجات وأفراد الأسرة والمرفقات المطبّعة عند
  التحقق من النسخة الاحتياطية، مع اختبار رفض الملفات الناقصة.
- استثناء نتائج الفحص وملفات SQLite المؤقتة من مراقبة ملفات التطوير،
  لمنع EBUSY وإعادة التشغيل الناتجة عن ملفات لا تمثل تغييرًا في المصدر.
- إضافة أمر npm run verify:databases للفحص المتكرر للقراءة فقط.

التحقق
- اختبارات Rust: نجح 27 اختبارًا في الجولة الكاملة؛ نجح اختبار النسخ
  الاحتياطية الجديد أيضًا. الجولة النهائية نجح فيها 26 اختبارًا، مع
  استبعاد اختبارَي الكشف الطويلين اللذين نجحا سابقًا ولم يتغير كودهما.
- اختبارات الواجهة: 43 ناجحًا، واختبار الصورة الخاصة متجاوز لعدم توفير
  مدخل خاص. مراجعة شاشات الموظفين والوارد والصادر والإعدادات بلا أخطاء JavaScript.
- الترحيل الفعلي باستخدام Rust اجتاز الاختبار على نسخ الإنتاج والتطوير
  والقاعدة المضمّنة؛ إعادة الترحيل لا تغير النتيجة ولا تحذف سجلات.
- أوامر API الـ81 مسجلة في الخلفية، وإصدارات التطبيق متوافقة.
- npm audit النهائي: صفر ثغرات.
- cargo audit النهائي: صفر ثغرات في قسم vulnerabilities. بقي تحذيران
  لـglib وproc-macro-error في تبعيات Linux غير الداخلة في بناء Windows.
- تشغيل Tauri Dev بالمكتبات المحدّثة نجح، بعنوان AutoHR (Development).
- النسخ الاحتياطية الفعلية: 9 ملفات AUTOHRBK2 بترويسات وأحجام سليمة.

تنظيف البيانات التجريبية بتفويض المستخدم
- حُذف 12 سجلًا وصفيًا قديمًا لملفات لم تعد موجودة.
- حُذف 27 ملفًا لا يشير إليه أي سجل مرفق أو بيانات وصفية.
- بعد التنظيف: 43 ملفًا مرتبطًا، صفر مرفقات مفقودة، صفر ملفات غير مرتبطة،
  صفر سجلات وصفية لملفات مفقودة. فحص SQLite والعلاقات ناجح.
- نسخة ما قبل التنظيف: verification/cleanup-20261008-164208/before-cleanup.zip.
- القاعدة المضمّنة تحتوي جداول HR إضافية محفوظة من السابق؛ لم تُحذف.

حدود التحقق
اختبارات الكتابة والاستعادة نُفّذت على بيانات معزولة، لا على إنتاج المستخدم.
لم تُفك النسخ الاحتياطية الفعلية لعدم توفر كلمة مرورها؛ سلامة الترويسة
لا تثبت سلامة المحتوى المشفّر. لم يُختبر جهاز ماسح أو طابعة فعلية، ولم
يُنفّذ بناء Production أو تثبيت أو نشر. النتائج ليست ضمانًا لغياب كل عطل محتمل.

الآثار المحلية
verification/database-audit.json: النتائج العددية لقواعد البيانات.
verification/*-attachment-findings.json: تفاصيل المراجع القديمة للملفات.
verification/bundled-before-update.db: نسخة القاعدة المضمّنة قبل التحديث.
verification/npm-audit-final.json وcargo-audit-final.json: نتائج الفحص الأمني.
verification/backup-header-audit.json: فحص ترويسات النسخ الاحتياطية.
مجلد verification مستثنى من Git لأن بعض آثاره قد تحتوي بيانات خاصة.
